# Shape Mode freeform tray runtime

## Supply and ownership

- `ShapeLevelDefinition.ToRuntimeData()` expands authored counts into `PlayerBlockEntries`, including inline footprints. `BlockManager` consumes that complete initial buffer once after grid cells are created. It does not use the preset-only compatibility `PlayerBlocks` projection.
- Every entry is constructed through the existing `BlockFactory`, `BlockController`, `BlockModel`, and `BlockViewModel` path. `_trayBlocks` is the current run's inventory; `BlockOnHand` projects its live, unplaced pieces for availability checks. Shape Mode has no preview or swap and never refills a hand slot. The legacy game-over check remains for non-Shape modes only; Shape Mode never publishes `GameOverEvent` when no block fits.
- `ShapeTrayPiece.PieceId` identifies an authored runtime entry for the run; tray blocks have `SpawnIndex = -1`. `IsPlaced` is permanent. A successful grid drop retains existing occupancy/placement behavior and cannot be picked up, regardless of the legacy pickup configuration.
- Retry/new shape-level events discard old tray inventory and rebuild the authored supply. Successful placement never changes the remaining pieces' positions or presentation sizes.

## Presentation and input

- `Gameplay.unity` serializes the actual `ShapeTrayPanel.prefab` RectTransform into `BlockManagerInstaller.shapeTrayPanel`. The reusable prefab uses the supplied `Tray_Panel.png` sprite, preserving its 909:541 aspect ratio. Prefab defaults are world `(0, -3.25)`, width `4.6`, and height approximately `2.738`; the Gameplay instance may override these values. Runtime packing and clamping use the instance's actual world bounds and configured inset, not those prefab defaults.
- In `Assets/QuackUp/Settings/Grid/Block/BlockManagerConfig.asset`, the **Shape Tray → Tray Block Scale** setting controls resting Shape Mode pieces independently of **Object Scale** (which continues to control other modes). `TrayBlockScale` defaults to `0.5`, has a positive Inspector minimum, and substitutes `0.5` for nonfinite, zero, or negative serialized input. The saved asset's existing `ObjectScale = 0.35` is unchanged; it is not a tray-size cap or fallback. The same section exposes `TrayTiltMin = -15`, `TrayTiltMax = 15`, and normalized symmetric `TrayInset = (0.1, 0.15)`. Insets exclude the orange rounded frame, blue bottom shadow, and rounded corner cutouts; they define a conservative rectangular playable interior.
- **Shared resting-scale invariant:** every piece in the entire initial supply has exactly the same effective `Scale`, starting from `TrayBlockScale` (saved value `0.5`). Fit caps, sparse packing, dense visibility retries and the separated fallback can only reduce that common value; they never shrink one piece independently. A one-, two- or four-atom shape therefore has identical atom size. Tilt and gameplay turns are sampled/preserved separately from scale and are not rerolled when a common-scale retry is needed.
- `ShapeTrayLayout` uses the authored starting count, never the remaining count: **six or fewer** fit complete tilted footprints into nonoverlapping cells; **seven or more** allow overlap without a universal cell-size cap. Dense placement reserves real atom hit patches against higher-sorted coverage. A failed search restarts the entire initial layout at a reduced common scale with fixed tilts/gameplay orientations (at most 48 search passes). The separated fallback also uses one shared reduction and rechecks pickability. Impossible bounds are rejected before spawning with an actionable enlarge-bounds/reduce-supply error; shrinking artwork cannot eliminate fixed world-space collider padding. The coverage check retains its conservative radius allowance; this change does not edit collider/prefab geometry.
- Pickup removes only visual tilt, uses existing grid-size presentation, and raises sorting order; return restores the same initial common resting scale. Gameplay orientation remains independent of visual tilt. Existing mode-specific player-rotation permissions are unchanged. `ShapeTrayPiece.Rotate` clamps the new complete footprint after a turn without rescaling. Deliberate rearrangement may overlap pieces; neither rearrangement nor successful placement triggers another layout or rescales remaining inventory.
- Dropping the pointer inside the full panel (including artwork padding) stores the new piece center, clamped into the inset playable interior using complete rotated presentation bounds. `DropBounds` is the full drop target and `TrayBounds` is the smaller usable interior. Tray return restores that piece's saved tilt, tray scale, sorting, and latest location. Invalid grid/outside drops restore the latest tray location without altering occupancy. Valid grid drops use the existing grid validator and commit path.
- The tray GameObject is hidden outside Shape Mode. `BlockManagerInstaller` always provides the keyed tray binding through a factory; legacy scenes resolve null. VContainer does not fall back to a constructor's default value when a keyed registration is absent.

## Legacy Gameplay UI visibility

- In `Gameplay.unity`, select `OverlayCanvas/GameplayPanel` → `GameplayPanelView` → **Shape Mode / Hide In Shape Mode**. This Unity-serialized GameObject array is editable in the Inspector and hides only its configured objects, not their siblings or the whole `Back` group.
- The saved scene assigns exactly `Back/NextQueue`, `Back/Hands`, `Back/Swap Icon`, `Back/Next Queue` (the separate label with a space), and `SwapButton` (a direct child of `GameplayPanel`). `Fit BG`, both Score objects, `BG`, and `Banner` are not targets.
- `GameplayPanelViewModel.CurrentGameMode` is an R3 read-only state seeded from `ILevelManager.CurrentGameMode` and refreshed on the existing keyed `GridManagerMessageHub` session-spawn event. LevelManager assigns its authoritative mode before publishing, including Classic/null runtime data, retry, and seamless Shape sessions. The View binds that state and owns only visibility presentation; subscriptions are disposed with their owners.
- Entering Shape Mode snapshots each unique non-null target's `activeSelf` before hiding it. Repeated notifications never overwrite that snapshot. Leaving Shape Mode restores those states rather than blindly enabling previously inactive objects; null, empty, duplicate, and destroyed target references are safe. Unlisted UI is untouched.
- `Tests/Panel/GameplayShapeVisibilityTests.cs` exercises initial/live MVVM binding, repeated transitions, authored inactive targets, null/empty/duplicate entries, subscription disposal, and actual saved-scene identities and hide/restore behavior. Run `FitMe.Panel.Tests` alongside tray tests; scene loading acknowledges only the same known stale reference errors as the existing tray fixture, never unrelated new errors.

## Shape Mode exhibition controls

- The Shape `Hint` button and free `Retry` button remain visible for the whole level. Hint has a four-use local allowance, shown by the `HintButton/Label` TMP field explicitly wired in `Gameplay.unity`; each `SpawnWithShapeLevelEvent` starts that level entry with four again. Shape hints do not spend the project-wide hint resource.
- A hint consumes one local use only after a definitive solver result (`Feasible` or `Infeasible`). Search-limit and invalid-input outcomes do not consume a hint. The count is reactive UI state owned by `ShapeHintController` and exposed through `GameplayPanelViewModel`.
- Feasibility is checked after a successful board placement and after Shape supply blocks spawn. A proven-infeasible state disables/tints Hint and starts persistent flashing guidance on Retry. Ordinary board changes do not dismiss this guidance; the `ClearGridEvent` retry path clears it after publishing `ContinueEvent` first, preserving the existing supply reset order.
- Shape Mode does not enter the global game-over flow. `BlockManager.GameOverCheck()` returns without publishing no-placeable/game-over events while Shape runtime data is active; Classic game-over behavior is unchanged.
- Focused verification: `GameplayRetryBehaviorTests` covers the local four-use cap, retry event order, button visibility and definitive-result spending; `GameplayShapeVisibilityTests` verifies the saved Hint-count binding. `GridManagerLifecycleTests.ShapeTray_GameOverCheckIsDisabledForShapeLevels` verifies the Shape game-over guard. This EditMode evidence does not claim a PlayMode/device presentation smoke test.
