How to decide — examples and snippets

Keep when a future feature may reuse the code. Remove when it has no callers and is replaced by a current system. Investigate when the value depends on a future design decision.

Example: PausableTimer

_timer = new PausableTimer(duration);
_timer.Pause();
_timer.Resume();

Keep it if timed boosters, energy recharge, or tutorial countdowns may need pause/resume. Remove it only if elapsed-time tracking plus UniTask is the permanent direction.

Example: ReloadScene

SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex);

Keep it for an intentional debug shortcut. Remove it if all scene changes must use the injected LoadSceneManager.

Example: unused asmdef reference

FitMe.GameData.asmdef
    references:
    - QuackUp.SceneManagement

Investigate first if editor-only or generated code may still use the assembly. Remove only after checking both runtime and editor paths.

Example: duplication

public class Settings { public float MusicVolume; }
public class UniversalSettings { public float MusicVolume; }

Refactor only when both classes represent the same concept and should share one source of truth. Keep as-is when they intentionally represent different scopes or save formats.
